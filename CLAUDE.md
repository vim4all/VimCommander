# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

VimCommander is a two-pane, Total Commander–style file manager with vim keybindings (a graphical vifm), written in Python with PySide6 (Qt Widgets). It targets Windows, macOS and Linux.

## Commands

```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt   # Windows: .venv\Scripts\...
.venv/bin/python main.py [LEFT_DIR] [RIGHT_DIR]                     # run the app
.venv/bin/python -m unittest discover -s tests                     # all tests
.venv/bin/python -m unittest tests.test_vim.KeyEngineTest.test_count  # single test
```

There is no linter configured; `pyrightconfig.json` only points Pyright at `.venv`. `build.py` makes a standalone, console-less PyInstaller build in `release/VimCommander/` (deps in `requirements-build.txt`). PyInstaller doesn't cross-compile: for the Windows `.exe`, run it from WSL with the Windows venv, `.venv-win/Scripts/python.exe build.py`.

Headless runs (for scripted GUI checks driven with `PySide6.QtTest`): set `QT_QPA_PLATFORM=offscreen`, and set `VIMCOMMANDER_CONFIG=/some/temp/config.json` so the run doesn't read or overwrite the user's real settings. Also set `XDG_DATA_HOME` to a temp folder on Linux (create it first, or Qt's trash fails; files under `/tmp` can't be trashed at all), so trash and undo tests don't fill the user's real trash. Wait with a `QEventLoop` + `QTimer.singleShot`, not `QTest.qWait`: qWait starves the worker threads (graph, search), so their results never arrive.

Development happens in WSL2 (`/mnt/d/...`). The Linux `.venv` can't be used from Windows. Drag and drop with Windows Explorer only works when the app runs natively on Windows, not through WSLg.

## Architecture

The code is the `vimcommander/` package; `main.py` just calls `app.main()`.

**Key handling flow.** `MainWindow` installs itself as an event filter on both panes' `QTableView`s and swallows every key press there. `key_name()` (app.py) converts a `QKeyEvent` to vim notation (`"j"`, `"<C-d>"`, `"<F5>"`). `KeyEngine.feed()` (vim.py) accumulates counts and multi-key sequences and returns an `Action(name, count, arg)`. `MainWindow.run_action()` dispatches it to the method `cmd_<name>`. Keys go in through `MainWindow.feed_key()`: when a binding is also the start of a longer one (a user `:map`), the engine waits; `_map_timer` (`timeoutlen`) calls `engine.flush()`, and a key that doesn't continue it is returned in `engine.leftover` and fed again. After every action, if the engine is in VISUAL mode, the selection is redrawn from `visual_anchor` to the cursor.

- **Adding a key** means adding a binding in `vim.py` (`NORMAL_KEYS` / `VISUAL_KEYS`, or `MOTIONS` for both modes) and a `cmd_<name>` method on `MainWindow`.
- **Bindings that take the next typed key as an argument** (`ma`, `'a`, `fx`) go in the `*_ARG_KEYS` tables.
- **A binding value can carry a fixed argument** after a colon (`"g3": "bar:3"`).
- `vim.py` must stay free of Qt imports so it stays unit-testable.
- **`:map` / `:noremap`** (session-only, from the `vimcommanderrc` run at start via `ex_source`) live in `MainWindow.maps` and are merged over the defaults and config `keys` by `apply_keys()`; values are `keys:RHS` (noremap: `run_keys(remap=False)` swaps in `base_bindings`), `remap:RHS` or `ex:CMD`. `vim.split_keys()` parses vim key notation (`<leader>`, `<cr>`, `<C-x>`). `run_keys()` types keys after `:` / `/` into the command line until `<CR>`.
- **Ranges** (`:'<,'>`, `:%`, `:3,8`, `:.,.+2`) are parsed by `RANGE` in `execute()`; `range_command()` tags those rows, then runs the rest.
- **langmap.** `KeyEngine.feed()` first runs `translate()` (the config's `langmap`, parsed by `parse_langmap()`; built-in `LANGMAPS["cyrillic"]`), except for the argument of `LITERAL_ARGS` (`f`/`F`). `key_name()` turns Ctrl + a non-Latin letter into `<C-д>` so the engine can map it. Only non-ASCII characters may be mapped.

**`:` commands** are dispatched by name to `ex_<command>` methods on `MainWindow` (`execute()`). The typed name goes through `actions.resolve()` first: an exact name, else vim's shortest form from `actions.SHORTEST` (`se` = `set`), else a unique prefix; ambiguity is reported. A trailing `!` sets `self.bang` while the handler runs (force: `:delete!`, `:rename!`, `:pdfextract!`, `:sort!`). `:set` takes saved options (`BOOL_OPTIONS`, `STRING_OPTIONS`) and session-only view toggles (`RUNTIME_OPTIONS`, read and applied through `runtime_options()`). `show_message()` also feeds `self.messages` for `:messages` (progress lines left out). Each pane keeps its last 10 result lists in `result_history` (`:colder` / `:cnewer`). `:!cmd` and `:<number>` are special-cased. The `/` search and `:` prompt share one `CommandLine` widget; the prompt label text (`":"` or `"/"`) tells them apart.

**Cursor vs. tags.** In a pane, the vim cursor is the view's *current index*, moved with `SelectionFlag.NoUpdate`. Tagged items are the view's *selection*. They are independent. `CursorDelegate` paints the cursor row as a translucent overlay so both are visible. `Pane.targets(count)` returns the tagged entries, or else `count` entries from the cursor. File operations use it and always skip the synthetic `..` entry (`Entry.is_parent`).

**Pane (pane.py).** Layout: `QTabBar` (hidden with one tab), a header row (drive `QToolButton` + path label), and a `QStackedWidget` holding the `FileView` and a `QuickView` (preview.py). `DirModel` lists a folder with `os.scandir` (or a zip folder via archive.py), sorts folders first, and prepends `..`. Sorting is a stable multi-pass sort: by name, then by the chosen key, then folders first. Folder sizes from `gs` live in the module-level `DIR_SIZES` cache. `Pane.cd(path, select=, record=)` is the single navigation entry point. It reloads the model, sets `pane.archive` (`(zip, inner)` or None), re-points the `QFileSystemWatcher` (debounced auto-reload), updates drive/free space, and records back/forward history. `reload()` keeps the cursor and tags by file name. Tabs: the current tab's state (path, history, sort) lives on the pane itself; the others are dicts in `pane.tabs`, swapped by `_save_tab()` / `_load_tab()`.

**File operations (fileops.py).** Copy, move, trash, delete and undo run on a Python `threading.Thread` inside a `Job` QObject. Signals (queued onto the GUI thread) report `progress`, ask about name clashes (`conflict` → `ask_conflict()` dialog → `job.answer()`; the worker blocks on a `threading.Event`), and `finished`. Copies go through a `.vctmp` file, so cancelling never leaves half a file. Each job fills `job.undo` with records (`created` / `moved` / `trashed`, plus `renamed` from `MainWindow.rename_many()`); `MainWindow.undo_stack` keeps them and `u` runs an `undo` Job. Trash uses the instance form `QFile(path).moveToTrash()`, because only it reports the path in the trash (needed for undo); the static form returns just a bool in PySide6. `start_job()` attaches a `ProgressDialog` (dialogs.py) that shows itself after 400 ms. `:pdfmerge` is a `Job("pdfmerge", pdfs, dest)` using `pdftools.Merger` (pages collected in memory, saved through a `.vctmp` only if every source was read). `:pdfextract` is a `Job("pdfextract", [(pdf, new_pdf)…])` with `job.pages` (parsed by `pdftools.parse_pages()` inside `extract()`, so a bad page list is an `OSError` per item); the new PDF goes next to its source, so it works in result lists. PDFium isn't thread-safe: every pypdfium2 call, in `preview.PdfRenderer` too, holds `pdftools.LOCK`.

**Archives (archive.py, Qt-free).** A path like `x.zip/dir/f.txt` is virtual. `locate()` returns `(zip, inner)` for the zip itself or anything in it; `inside()` only for paths strictly inside, so code that handles files must use `inside()` (a real `.zip` file is copied, not extracted). Zips are read-only except for deleting: `MainWindow._read_only()` guards every other changing command; `cmd_delete` / `cmd_trash` in a zip run a `delete` Job, which calls `archive.remove()` (rewrites the zip through a `.vctmp` file, no undo).

**Context menu.** `FileView` emits `context_menu(row, pos)` for mouse right-clicks only; the Menu key and Shift-F10 are normal key bindings (`context_menu` action), so there is no double menu. On Windows, `winshell.show_menu()` builds Explorer's menu through `IContextMenu` with ctypes. While it is open, `MainWindow.nativeEvent` forwards menu messages to `IContextMenu2/3` so self-filling submenus (Send to, Open with) work. The shell's `rename` / `delete` verbs are matched by language-neutral verb (the labels are localized) and returned to the app instead of run. Elsewhere, or with Ctrl held, `_own_menu()` builds a QMenu from `_menu_items()`.

**Drag and drop.** `DirModel.mimeData` exports file URLs, so drags out to other apps work. `FileView.dropEvent` and `LaunchBar.dropEvent` emit `files_dropped(paths, target_dir, move)`. Both are connected to `MainWindow.on_drop`, which starts a copy or move job. A plain drop copies; Shift+drop moves.

**Launch bar (bar.py).** A `QToolBar` of `BarItem`s (name, path, args, icon). An item whose path is a folder navigates the active pane via `folder_requested`; anything else is launched with `QProcess.startDetached`, falling back to opening it with `QDesktopServices`. Argument placeholders are `%d` (current folder), `%o` (other pane's folder), `%f` (file under the cursor) and `%s` (selected or dropped files), expanded by `expand_args()`. The bar has no access to the panes; it gets that state from `context_provider`, which `MainWindow` sets to `bar_context()`. When the bar changes it emits `changed`, which makes `MainWindow` save the settings.

**Settings (config.py).** A single hand-editable JSON dict: `VIMCOMMANDER_CONFIG`, else `config.json` next to the executable in a frozen build (portable), else Qt's `AppConfigLocation`. `DEFAULTS` lists every user option; `with_defaults()` merges a file over it (nested dicts one level deep). `load()` raises `ConfigError` on bad JSON. `MainWindow.save_settings()` re-reads the file and writes only the app's state into it (bar items, bar label/visibility, marks, pane folders), so hand edits survive; it saves nothing while the file is broken. It runs on bar changes, on mark changes and in `closeEvent`. A `QFileSystemWatcher` on the file calls `reload_config()` → `apply_config()`, which re-applies keys (`vim.user_bindings()`; a value starting with `:` becomes the `ex` action), pane options (`Pane.configure()`), the bar and marks. Window size and font apply only at start. If the file has no `"bar"` key, `default_items()` provides the default bar for the platform. Configured programs (`programs.*`) are command lines run by `bar.run_command()`. User `:` commands (`commands`) are expanded in `execute()` before the built-in `ex_` methods.

When adding an option, add it to `DEFAULTS` and to the Configuration section of README.md.

**zoxide (zoxide.py, Qt-free).** `Pane.folder_changed` → `MainWindow.zoxide_add()` queues `zoxide add` on a worker thread (never blocks the GUI). `:z` uses `zoxide query --exclude <cwd>`, `:zi`/`gz` list `query --list --score` in `ZoxideDialog`, filtered with `zoxide.matches()` (zoxide's keyword rule). Tests must set `_ZO_DATA_DIR` to a temp folder so they don't write to the user's zoxide database.

**Vim grammar.** `vim.py` generates `y`/`d` + motion bindings (`OPERATORS` × `OPERATOR_MOTIONS`) as `yank_motion:<motion>` / `cut_motion:<motion>`; the engine accepts a second count after an operator (`self.inner`) and multiplies it with the first. `MainWindow._motion_paths()` runs the motion's `cmd_` method and takes the rows between the start and end. `run_action()` records `REPEATABLE` actions in `last_change` for `.`; `execute()` records `REPEATABLE_EX` commands. Search, `*`/`#`, hlsearch and the `=` filter all compile patterns with `pattern_regex()` (regex, shell pattern if only `*`/`?`, literal if invalid, smartcase). `:set` handles the boolean options in `BOOL_OPTIONS` and saves them with `save_settings(options)`. Line numbers are the table's vertical header (`DirModel.headerData` for `Vertical`, refreshed on cursor moves when relative). Command-line history lives in `MainWindow.history` (per prompt, saved in the config).

**Registers, undo/redo, macros.** `KeyEngine` reads a `"x` prefix into `Action.register`. `MainWindow.store()` / `cmd_paste()` use `self.registers` (`'"'` = unnamed, always updated); `"+`/`"*` go through clipboard.py, which writes file URLs plus the copy/cut markers of Explorer (`Preferred DropEffect`), KDE and GNOME, and tags its data so `release_at_exit()` can clear it: on Linux, PySide 6.12 segfaults at exit if the clipboard still holds Python-created QMimeData. Undo: every `fileops` undo step appends its inverse record to `job.undo`, so redo is the same `_undo` run on those records (`_undo_redo()` moves entries between `undo_stack` and `redo_stack`). Macros record raw key presses (key, modifiers, text) with the app-wide `MacroRecorder` filter, only for the focus widget, so `:` line and dialog keys are included; playback sends them to `QApplication.focusWidget()` one per zero-length timer tick, restarting the timer before each send so keys reach a dialog the macro opens.

**Graph (graph.py Qt-free, graphview.py).** Modes: tree, sunburst, notes, code. Quick view shows a folder (or the current folder for `..`) as a `GraphView`. `graph.scan_tree()` builds nodes level by level (files grouped per extension, children beyond `KEEP[level]` folded into a "more" node, leaf folders marked `complete=False`); `fill_sizes()` adds full leaf sizes within a time budget; `layout_radial()` places them. Notes mode: `scan_notes()` + `find_links()`, laid out by `ForceLayout.step()` (grid-based repulsion), one step per animation frame. A `_Scanner` runs in a thread; results carry a token so stale scans are ignored, and a 150 ms debounce avoids scanning while the cursor moves. Options live in the shared `graphview.OPTIONS` (from the config's `graph`); node clicks go to `MainWindow.on_graph_open()`. graphview imports `human_size` lazily because pane → preview → graphview would be a cycle.

**Tools.** `actions.py` describes every action and `:` command; `tests/test_tools.py` fails if a key or `ex_` method has no description, so keep it in sync. The which-key panel (`whichkey.py`) is filled by `MainWindow.whichkey_entries()` from the engine's pending state after `which_key_delay` ms. The palette (`palette.PaletteDialog`) is built from `palette_entries()`; the file finder (`palette.FileFinder`) indexes in a thread and ranks with `fuzzy.rank()` (regex prefilter, then best-alignment scoring) plus a zoxide frecency bonus. `:bulkrename` uses `rename.bulk_text()` / `parse_bulk()` and then `rename_many()`. `compare.compare_trees()` feeds `:compare` (tags) and `sync.SyncDialog`, whose plan runs as a `Job("sync", [(src, dest)])`. `activity.py` holds both the scan and its dialog. The sunburst is `graphview` mode "sunburst" (arcs computed in `_layout_arcs()` each paint, hit-tested in `_arc_at()`).

**Result lists (pane.Results, results.py).** A pane can show `pane.results` (title, root, paths) instead of a folder: `show_results()` sets `pane.path` to the root (so `bar_context`, settings and tabs keep working), `DirModel.load_results()` lists the paths that still exist with `Entry.shown` = path relative to the root (displayed and sorted by name; `Entry.name` stays the basename, so rename patterns work), and `reload()` goes to `refresh_results()`. `cd()` leaves the list; `cmd_parent` calls `leave_results()`. Tab state carries `results`. `MainWindow._read_only(pane, into=True)` refuses paste / F5 into / mkdir / touch in a list; `rename_many()` renames each entry inside its own folder and `_renamed_in_lists()` updates every list, tab and the shelf (also after move jobs, from their `moved` undo records). `start_results()` fills a list from a producer (a function of a stop Event yielding batches of paths, e.g. `results.find_paths`) run by `results.Search` in a thread, refreshing at most every 250 ms; `self.searches` holds the running one per pane (`Esc` stops it). `show_result_list()` shows a finished list (grep, file finder `Ctrl-Enter` = `how == "all"`, activity `result_list`, `:shelf list`).

**Grep, diff, shelf.** `grep.py` (Qt-free: `compile_pattern` smartcase, `parse_globs`, `grep()` generator with a `Stats`) feeds `grepdialog.GrepDialog` (thread worker with a token, preview with ExtraSelections); Enter calls `MainWindow.edit_at()` with `programs.editor_line` (`%l` is expanded by `bar.expand_args` from `ctx["line"]`). `textdiff.align()` (Qt-free) lines two files up into `Row`s (same / change / delete / insert, filler rows have no line number); `diffview.DiffDialog` shows them in two synced `QPlainTextEdit`s with line numbers prefixed (`self.offset` chars) and colors as ExtraSelections, and handles its own vim keys (`]c`, `[c`, `gg`…). `shelf.Shelf` is a `QDockWidget` (state `shelf` / `shelf_visible` in the config); its list handles its own keys and drag and drop, and emits `goto` / `back` / `command`; `ex_shelf` / `ex_zip` start a `Job("zip", paths, zip_path)` (`fileops._zip`, removes a half-made zip on cancel). The code graph: `graph.scan_code()` with `_CodeIndex` resolving Python / JS-TS / C-C++ / Go / Rust imports by regex, directed edges, `Node.count` = imported by; graphview treats "notes" and "code" alike (`FORCE_MODES`).

**Space, git, links, columns, rules, sessions.** `cleanup.py` (Qt-free) holds `reclaim()` and `dupes()`, producers that yield `(path, note[, set])`; `start_results()` puts notes in `Results.notes` (shown after the name) and sets in `Results.groups` (for `:dupes tag` via `keep_one()`). Git: `Pane.listed` (emitted by every `cd()`, `show_results()` and `refresh_results()`) starts the pane's debounced `git_timer` → `run_git()`, which runs `gitstatus.status()` in a `results.Search` and calls `pane.set_git(folder_kinds(...), branch)`; `DirModel.git` colors names (`"*"` = the whole folder is ignored), `self.git_repos` keeps each pane's last status. `:linkpanes` stores `self.link` (both roots); `follow_link()` (from `folder_changed`) and `follow_link_cursor()` (from `cursor_moved`) only act for the active pane and set `_linking` to avoid echoes; `mark_unique()` fills `DirModel.unique`. Miller columns: `Pane.columns_split` holds `parent_column` / `stack` / `right_column` (a `ColumnList` or a second `QuickView`), refreshed by `update_columns()`. `rules.plan()` (Qt-free) → `RulesDialog` → one Job per (action, destination). Sessions: `Pane.session_state()` / `load_session()` (tabs with `Results.to_dict()`), stored in the config's `sessions` via `save_settings({"sessions": …})`.

**Terminal pane, WSL, memory map.** `:vterm` / `Ctrl-w t` puts a `termview.TermView` into the other pane's `stack` (`Pane.show_terminal()`, `pane.term`, `shows_terminal`; the header row hides). The program runs in `ptyproc.PtyProcess` (`pty.fork` or pywinpty's ConPTY; ConPTY never reports EOF, so `_check_alive` polls). A reader thread emits text; `TermScreen` (pyte `HistoryScreen` + alternate screen 1049, ignores `CSI > … m`) keeps the screen, `paintEvent` draws runs of equal attributes. `termshell.shell_command()` builds argv/env per kind (`wsl` / `powershell` / `cmd` / `posix`) with a prompt hook that emits OSC 7; `_output` scans OSC 7 → `cwd_changed` → `MainWindow.on_vterm_cd()`; the file pane's `folder_changed` → `follow_vterm()` → `TermView.cd()` (only `at_prompt`, i.e. after an OSC 7 with nothing typed). `activate()` on a terminal pane focuses the terminal and keeps `self.active` on the file pane. `wsl.py` translates `D:\x` ⇄ `/mnt/d/x` and `\\wsl.localhost\NAME\…`; the line-mode panel also takes `wsl` (kind `"wsl"`, marker carries `$WSL_DISTRO_NAME|$PWD`). `termshell.ANSI` holds the 16 colors (set by `theme.apply`). `memmap.parse()` (Qt-free) reads GNU ld / Keil maps and ELF into `Region`s with a `Node` tree; `memmapview.MemMapView` (in `QuickView`, parsed on a thread with a token) draws bars + a `graph.squarify` treemap and emits `not_a_map` so other `.map` files show as text.

**STEP models (step.py Qt-free, stepview.py).** `step.StepFile` splits the DATA section with one regex and parses an entity's arguments on first use (`get()` → `{TYPE: args}`, several types for a complex `( A() B() )` entity; `Ref` = `#n`). `build()` unions representations linked without a transform, links assembly children through `REPRESENTATION_RELATIONSHIP_WITH_TRANSFORMATION` (`ITEM_DEFINED_TRANSFORMATION`: item2 · item1⁻¹, as Open CASCADE reads it) and `MAPPED_ITEM`s, then walks from the roots placing each solid's cached `Piece`s (`_Builder.item_pieces()`). Planes are one polygon with holes (`edges=True`), analytic surfaces a (u, v) grid of cells inside the unwrapped boundary (`_grid_cells()`), a B-spline face only when its boundary covers the whole patch; every face also gets an outline piece (`fill=False`). `MAX_PIECES` caps it (`partial`). `StepView` sorts pieces by size once, then each paint picks as many as fit in `FRAME_TIME` (moving) or `STILL_TIME` (still, after `_settle`), depth-sorts them by centre and draws them back to front. The reader takes a stop Event (`step.Stopped`); `QuickView._step()` sends non-STEP `.stp` files (SystemTap) to text. `stl.parse()` (Qt-free) makes the same `Model` (`mesh=True`: triangles are cells whose corners snap; `feature_edges()` adds outlines below `FEATURE_LIMIT`); a reader raises `step.NotAModel` for another kind of file, which `StepView` turns into `not_a_model` (shown as text / hex). `prepare()` builds the drawing items in the reading thread. Part names: `build()` maps representations to `PRODUCT` names through `SHAPE_DEFINITION_REPRESENTATION`, and `walk()` joins the names below the top product into `Model.labels` (`part_of` per piece). Measuring: each drawn item keeps its polygons and a screen circle (`_drawn`); `_piece_at()` finds the front face, `_surface_point()` intersects the view ray with its plane, `_pick()` snaps to circle centres (`Piece.marks`, from `_Builder.edge_centre`) or corners in front within `SNAP` px. `zv` (`cmd_model_keys`) calls `StepView.focus_keys()`; the view handles its own keys (`TabFocus`, so a click doesn't take them) and emits `leave`, which focuses the file pane.

**Natural sort, CSV plot, notebooks, .ioc, quickfix.** `SORT_KEYS["name"]` and `ColumnList` sort with `pane.name_key()`: `natural_key()` (digit runs as ints; `(parts, name)`, so str and int never meet) while `pane.NATURAL["on"]` (set from `natural_sort` in `apply_config()`, `:set natural`). `zp` (`cmd_plot`) flips `preview.PLOT["on"]`; `QuickView` then sends CSV files to `plotview.PlotView` (in a `QScrollArea`), which runs `tabular.read_columns()` in a thread (token + stop Event): the head's first 200 rows decide the numeric columns (numbers in at least half the rows that hold any), the header row (labels on most columns) and a unit row, then rows go through a fast `map(float, itemgetter(...))` path into one flat `array('d')`, sliced into columns; the x axis is a rising time-named or first column, else the row number. Traces are min/max per pixel column (`bisect` on x), cached per `(span, width)`; `not_numeric` makes quick view show the table. `PlotView.load()` takes the reader: `ltspice.read_raw()` (Qt-free; header in UTF-16 or ASCII, binary or text samples, AC as dB, `operating_point()` for one-point files) gives `.raw` files the same plot. `PlotView.set_x()` puts any column on the x axis (clicking a strip's name; `_labels` holds the clickable rects): a rising one keeps the line path, any other is a scatter (`_make_scatter`: rows in the span, at most `SCATTER_POINTS` drawn, stats over all). `:find` takes `results.parse_find()` conditions (`FindFilter`: size, age, type) passed to `find_paths()`. `notebook.convert()` (Qt-free) turns `.ipynb` into Markdown (code fenced with the kernel's language, outputs fenced as `output`, images as `nbimage:N`, which `MarkdownView.loadResource` serves; Qt's importer drops `![](…)` without alt text) for `MarkdownView.show_notebook()`, which shades code blocks by `BlockCodeLanguage`. `cubemx.parse()` reads `.ioc` properties into a `Project` shown with `show_html()`. Result lists keep `Results.index` (set by `gf`, `]q`, `[q`); `qf_step()` goes to the item in its folder; `:cdo` runs `!COMMAND` per item through `fill_shell()` in a `results.Search` (`self.cdo_run`, `Esc` stops) or a `:` command per item with the cursor on it (`_cdo_command`, list reloads tracked by `model.entries` identity).

**Grid, terminal, share.** `pane.GridView` (QListView in IconMode) shares the pane's model *and selection model* with `FileView`, so cursor and tags are one; both get mouse/drag/drop behaviour from the `ViewBehavior` mixin. `Pane.list_view` is whichever is shown; code that scrolls or measures uses it (`visible_range()`, `row_step()` for j/k in the grid). While the grid is shown, `view.setFocusProxy(grid)` makes the many `pane.view.setFocus()` calls work. Thumbnails: `grid.ThumbLoader` (one, made by `pane.thumbs()`) decodes scaled images in 3 threads, LIFO, cached by (path, size, mtime); `GridDelegate` asks it while painting. `terminal.Terminal` is a QDockWidget running the shell with QProcess, line by line (no pty): after each command it writes a marker command that prints `__VC_DONE__<cwd>__`, which ends "busy" and reports the folder (`cwd_changed` → the pane cds; the pane's `folder_changed` → `follow()`). PowerShell reads stdin in the OEM code page, so non-ASCII lines are sent base64-wrapped. `share.ShareServer` (Qt-free, ThreadingHTTPServer, random token in every URL, uploads by PUT, folders zipped on the fly) runs while `sharedialog.ShareDialog` is open; the QR code comes from `segno` (in requirements.txt).

**SSH folders (remote.py).** A remote location is an `sftp://[user@]host[:port]/path` URL (`remote.parse()` → `Location`; `remote.join/dirname/basename` work for both kinds of path; `from_spec()` turns `user@host:path` into a URL, `~` resolved by `REMOTE.resolve()`). `remote.REMOTE` holds one paramiko connection per host key; GUI-thread calls (list, stat, rename, mkdir, small reads) share one SFTP channel under a lock, while each `Job` opens its own channels (`Job._channel()`) and copies through `remote.Endpoint` / `copy_tree()` (local or remote on either side). `Pane.remote` is set by `cd()`; `DirModel.load` lists remote folders, and anything that uses local file functions on `pane.path` must check `pane.remote` (`MainWindow._local_only()`). Password and host-key prompts are `Remote.ask_password` / `ask_host`, set to dialogs by `MainWindow`. Editing downloads to a temp copy (`_local_copy(edit=True)`) watched by `edit_watcher`, uploaded on save. The terminal runs a remote shell over a paramiko channel (`Terminal._start_remote`) with the same marker protocol; `follow()` swaps the shell when the pane moves between hosts. `compare.join()` / `delete_plan()` / `mirror()` make `:synchronize` and `:mirror` work across. Tests use `tests/sshserver.py`, a paramiko SSH server (password "pw") that emulates Windows OpenSSH paths (`/D:/x`).

**FTP (ftpfs.py, Qt-free).** `ftp://` / `ftps://` URLs parse to a `Location` with `scheme` (`loc.is_ftp`; `loc.key` gets the scheme in front, `loc.url()` builds from `address`). `ftpfs.FtpClient` mimics the subset of paramiko's `SFTPClient` the code uses (errors become `OSError`), and `remote.FtpConnection` mimics `Connection` (`client = None`: no shell), so listing, jobs, `copy_tree` and compare work unchanged. FTP can't read and write on one control connection at once, so `Job._endpoint(dest=True)` opens a separate channel for an FTP destination. Tests: `tests/test_ftp.py` with pyftpdlib (in requirements-build.txt; skipped without it).

**Copy queue (jobs.py).** `start_job()` queues a job whose op is in `QUEUED_OPS` while another one runs (`self.job_queue`, config `queue_jobs`); `on_job_done()` → `_start_queued()` starts the next unpaused one. Only jobs started at once get a `ProgressDialog` (its *Background* button shows the panel); every job has a row in `JobsPanel`. `Job.pause()` clears an Event that `_check()` waits on, so pausing stops between chunks.

**Music player (music.py Qt-free, player.py).** `gm` / `:play` → `MainWindow._play_targets()` (tagged, a folder via `music.tree_tracks()`, an `.m3u`, or the cursor's file with the rest of `folder_tracks()`) → `_start_playing()`. `_player()` imports player.py lazily (QtMultimedia is PySide6-Addons; a missing import is a message), making `Player` (owns the `QMediaPlayer`, created on the first track; `order` / `pos` give the play order, shuffled by `music.shuffled()`), the `PlayerBar` dock (no title bar, `NoFocus` controls) and one `PlaylistView`, which `Ctrl-w m` puts in the other pane's `stack` (`Pane.show_playlist()` / `shows_playlist`; `Pane.covered` = terminal or playlist; `activate()` focuses it). Options are saved as `player` (debounced). On Linux, player.py sets `QT_AUDIO_BACKEND=pulseaudio` before importing QtMultimedia when PipeWire has no `client.conf` (`music.audio_backend()`): libpipewire aborts the process otherwise (WSL).

**Trash and persistent undo (trash.py Qt-free).** `trash.items()` reads the freedesktop.org trash (`trash_dirs()`: home + `$top/.Trash-$uid` per mount point, `.trashinfo` parsed by `parse_trashinfo()`), the Windows Recycle Bin (`$I` files, `parse_index()` v1/v2) or macOS `~/.Trash` (no origin). `:trash` → `dialogs.TrashDialog` → `Job("restore", [(trash_path, dest)])` (adds `created` records, so `u` re-trashes) or `Job("purge", paths)`; `fileops.restore_from_trash` (undo of `trashed`) is `trash.restore()`. Undo entries are `(description, records, time)`; while `persistent_undo` is on they are loaded from and saved to `undo.json` next to the config (`config.load_undo()` / `save_undo()`, records validated by `UNDO_KINDS`) after every `_record()` and undo/redo job.

**`:g` and hex.** `execute()` sends `GLOBAL` matches to `global_command()`: tags the matching rows (`Pane.tag_rows()`), then runs `GLOBAL_ACTIONS` (d / d! / y), `normal KEYS` (fed through the engine) or a `:` command. `tabular.py` (Qt-free) parses CSV/TSV for `preview.CsvView` (only the first `TEXT_LIMIT` bytes; header column tooltips carry `column_stats()`). `:recent` lists `MainWindow.recent` (filled by `add_recent()` from the open/edit paths, saved in the config) or runs `results.changed_files()`. `preview.HEX["on"]` (`:hex`) makes `QuickView` show every file through `_hex()` / `hexdump()`; binary files always go there.

Big tool windows size themselves with `sizing.fit_window(window, w, h)` (capped to the screen, centred, maximize button); give their long labels word wrap or an `Ignored` size policy, or the minimum width beats the cap. The which-key panel shows only while a prefix is pending and the main window is active; its timer is stopped before an action runs, because the action may open a modal dialog.

`rename.py` (Qt-free) holds the `{name}{ext}{n:3}` patterns and the `:s/re/new/gi` parser. `key_name()` adds `C-`/`A-`/`S-` prefixes only to F-keys and Delete (`<S-Del>`, `<A-F1>`, `<S-F10>`). Tab completion on the `:` line is `MainWindow.completions()`; paths are completed for `PATH_COMMANDS`.

When changing keys or commands, keep `HELP` in app.py and the key and command tables in README.md in sync (commands are grouped by topic there). README.md is for users, grouped into parts (finding, working with files, viewing, panes, comparing, terminal, servers); the module and test lists are in DEVELOPMENT.md: add new modules and test files there. `F1` / `:help` shows `HELP` in `helpview.HelpDialog`, which parses its format: a `<b>Title</b>: …` line starts a section, `&nbsp;&nbsp;…` lines continue it, and the text before each ` = ` (split at `, `, `; ` or two spaces) is shown as keys. New lines must follow that format, or they render as plain text or in the wrong section.
